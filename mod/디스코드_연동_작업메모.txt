1. 최종 목표

- 마인크래프트 채팅과 탭리스트에 연동된 디스코드 프로필 사진을 표시한다.
- 채팅은 사진·이름·그래픽 세로 구분선·본문 순서로 표시한다. 단순 문자 |를 사용하지 않는다.
- OP가 /displayname 또는 /표시이름 명령으로 한글 표시 이름을 편집한다.
- 실제 텍스트 에디터처럼 선택한 구간마다 색상·그라데이션·굵기를 적용하고, 한두 글자 안에서도 그라데이션이 부드럽게 이어지게 한다.
- 디스코드에서 온 메시지는 프로필 사진 앞에 Discord 아이콘을 추가한다.
- 게임에서 디스코드로 보내는 메시지는 고정된 “서리” 이름 대신 플레이어에게 연동된 디스코드 이름·@아이디·프로필 사진으로 표시한다.
- 계정 연결은 봇에게 명령을 입력하는 대신 플레이어 PC에서 Discord 인증창을 여는 Social SDK 방식으로 개선한다.

2. 현재 반영한 내용

- 탭리스트 프로필 사진, 그래픽 채팅 구분선, OP 표시 이름 편집기 구현.
- 한글·부분 선택 서식·글자 내부 그라데이션·실행 취소/다시 실행 구현.
- 디스코드 → 게임 메시지에 Discord 아이콘 추가.
- 게임 → 디스코드 메시지는 하나의 봇 소유 웹훅을 재사용하고 메시지마다 연동 프로필을 적용하도록 변경.
  Discord의 “앱” 표시는 유지된다. 실제 사용자 계정으로 직접 메시지를 보내는 방식은 아니다.
  봇에 채팅 채널의 “웹훅 관리” 권한이 필요하다. 권한 오류 시 기존 봇 중계로 전달한다.
- Social SDK용 게임 내 연결 버튼, Java ↔ C++ 실행 프로그램 연결 코드, 서버의 PKCE/OAuth 검증 코드를 작성했다.
- 기존 6자리 코드 연동은 대체 방법으로 유지한다.

3. 반드시 구분할 현재 상태

현재 배포 jar에는 공식 Social SDK DLL과 빌드된 C++ 실행 프로그램이 포함되어 있지 않다.
따라서 현재 jar만 설치하면 Social SDK 인증창은 작동하지 않는다.
SDK 연결은 소스 코드와 빌드 절차를 준비한 단계이며, 네이티브 빌드·실제 인증까지 완료한 상태가 아니다.
SDK 구성 요소가 없는 클라이언트에서는 인증창 버튼이 비활성화되고 코드 연동을 사용한다.

- 배포 파일: build/libs/newyear-countdown-1.2.16.jar
- Java 전체 컴파일 및 테스트 272개 통과.
- 테스트 범위: Java 로직과 로컬 HTTP 모의 서버 기반 검증.
- 실제 인게임 화면, C++ SDK 프로그램 빌드 및 실제 Discord 인증창은 아직 검증하지 못했다.

4. Social SDK 연결 구조

Java 마인크래프트 모드
  → 플레이어 PC의 C++ 연결 프로그램 실행
  → 공식 Discord Social SDK 호출
  → Discord 앱/오버레이 또는 브라우저 인증창
  → 승인 코드를 Minecraft 서버로 전달
  → 서버가 PKCE 검증값과 Client Secret으로 코드를 교환하고 Discord 계정을 확인
  → 계정 연결 저장 및 게임 접속 계속

C++ SDK라도 Java 모드와 연결할 수 있다. Java가 별도의 C++ 프로그램을 실행하고 결과를 주고받는 구조다.
플레이어에게 C++ 개발 도구를 설치하게 하지 않고, 빌드된 프로그램과 필요한 SDK 런타임을 배포한다.
서버에는 네이티브 SDK가 필요 없다. Client Secret은 서버에만 둔다.

5. 사용자가 질문한 750MB SDK 용량

750MB SDK 압축 파일 전체를 모드에 넣는 것이 아니다.
Windows x64 배포 시 필요한 주요 파일은 다음과 같다.

- Release 버전 discord_partner_sdk.dll
- 빌드된 newyear-discord-social.exe
- 해당 SDK 버전에 필요한 추가 런타임 및 라이선스/고지 파일

헤더·.lib 등 빌드용 파일, 디버그 파일, 지원하지 않을 플랫폼용 파일은 플레이어 배포에서 제외한다.
인증만 사용해도 SDK DLL을 기능별로 임의로 잘라낼 수는 없다.
최종 추가 용량은 실제 Release DLL과 런타임 의존 파일을 확인해야 알 수 있다. 아직 정확한 용량은 측정하지 않았다.

6. 다음에 이어서 할 일

1) 사용자가 내려받은 공식 C++ SDK ZIP 또는 압축 해제 폴더 경로를 확인한다.
   사용자는 SDK가 750MB라고 했지만 파일 경로는 아직 전달하지 않았다.
2) SDK 버전·폴더 구조·Windows x64 Release DLL 크기·필수 의존 파일을 확인한다.
3) 공식 SDK 헤더와 라이브러리로 C++ 연결 프로그램을 빌드하고 실제 API 호환성을 검증한다.
4) 필요한 런타임만 모드에 포함하고 최종 jar 용량을 확인한다.
5) 기존 봇과 같은 Discord 애플리케이션의 Social SDK 활성화 및 OAuth 설정을 확인한다.
   - Redirect URI: http://127.0.0.1/callback
   - 서버 환경 변수: DISCORD_CLIENT_ID, DISCORD_CLIENT_SECRET
   - 기존 봇 토큰: DISCORD_BOT_TOKEN
   - Client Secret은 채팅으로 받거나 클라이언트 배포물에 넣지 않는다.
6) 실제 플레이어 PC에서 인증창 열기·승인·취소·시간 초과·재접속을 검증한다.
7) 게임 안의 아이콘/프로필/편집기 표시와 양방향 채팅을 확인하고 서버·클라이언트에 같은 버전을 배포한다.

7. 이어서 볼 파일 및 명령
